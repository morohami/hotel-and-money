### タイプの扱い

- タイプは公表者の区分そのまま（観光庁は「旅館」「リゾートホテル」「ビジネスホテル」「シティホテル」、京都市観光協会は「ホテル」「旅館」、ポラリスはエリア、星野は投資区分）。自分で推測してタイプに振り分けたものはない。
- ビューアでタイプを「旅館」等にしたとき、地図は観光庁のタイプ別値だけを使う。ADR・RevPARはタイプ別の公表がないので、タイプが「全体」以外なら地図は (未) と表示する。
- 外国人比率（タイプ別）＝観光庁 第4表の外国人延べ宿泊者数÷延べ宿泊者数。

### 新しい月の足し方

1. 観光庁の第2次速報が出たら（毎月末ごろ。2026年8月分は2026-10-30予定）：
   - 観光庁の宿泊旅行統計調査のページ（https://www.mlit.go.jp/kankocho/tokei_hakusyo/shukuhakutokei.html ）から、その月の「集計結果（Excel）」と「報道発表資料（PDF）」のURLを取る。
   - `build_monthly.py` の `MLIT_SOKUHO2` と `MLIT_PRESS` に `"2026-08": MLIT + "00xxxxxxx.xlsx"` の形で1行ずつ足し、`MLIT_LATEST` をその月にする。推移表（`MLIT_SUII`）のURLが変わっていたら差し替える。
   - 第1次速報だけ出ている月は `MLIT_SOKUHO1` に足す（全国値だけ入り、都道府県は (未) になる）。
2. 月を表示に足す：`MONTHS` の末尾に `(2026, 9)` のように足す（ビューアのカレンダーもこれで増える）。
3. REIT等（翌月25日前後）：
   - いちご：`ICHIGO_PDFS` に `("2026-09", "公表日YYYYMMDD")` を足す。PDF内の「YYYY年M月度」が対象月と違うと止まるので、取り違えは起きない。
   - 星野・JHR・ポラリス：Excelは同じURLが上書き更新される（URLが変わったら `build_area_map.py` の `CONFIG["reit_files"]`、または `POLARIS_XLSX` を差し替える）。星野は新しい期のシートが増えても自動で読む。
   - インヴィンシブル：TDnetのPDFのURLを `INV_PDFS` に足す。
   - 京都市観光協会：URLは月から自動で作る（hotelYYYYMM）。
   - 森トラスト：`python3 fetch_dynamic_pages.py moritrust` を先に実行。
4. `python3 build_monthly.py --refresh` → `python3 verify.py` を実行し、`data/verification_summary.csv` の「不一致」が（参考）の行以外で0であることを確かめてから配る。
5. 2027年1月分からは前年（2026年）も観光庁の新系列に入る。`read_suii_occ` が読むシート（「4-1」と「旧4-2」）と、`people_source` の前年の出どころ（年の確定値）を見直す。

### 限界

- 観光庁は2026年1月分から層化基準を変えた（従業者数→客室数）。2026年の前年差には見直しの影響が含まれ得る。
- 都道府県×タイプには標本の少ないものがある（例：大阪府の旅館は延べ5.6万人泊）。大きな前年差は1施設の動きで出ることがある。
- ADR・RevPARの定義は公表者ごとに違う（サービス料の扱いなど）。ソース間で水準は比べず、前年比の方向を見る。
- 京都市観光協会の要約ページは前年差の符号を文で書いている。向きが書かれていない月（2025年10月のホテルOCC：差1.3ptとだけ記載）は前年差を (未) にした。

## 1. 観光庁 宿泊旅行統計調査で取れたもの

- 最新月は **2026年8月（第1次速報）** だが、8月1次速報のExcel（M3）は全国値だけで、都道府県別は載っていない。都道府県別の最新は **2026年7月（第2次速報）**。地図1はこの7月で作った。8月2次速報は2026-10-30公表予定（M2、2026-10-26）。
- 全国（M2、2026-10-26）：2026年8月 OCC 64.4%（前年同月差 −1.3pt）、延べ宿泊者数 6,268万人泊（前年同月比 −6.7%）、外国人 1,264万人泊（同 −10.3%）。2026年7月 OCC 61.0%（同 −0.2pt）、外国人比率 24.7%。
- 推移表（M1）には、2026年1〜7月の都道府県別の月次（新系列）と、2025年12月以前の月次（旧系列）が両方入っているので、1ファイルで前年同月比が計算できる。

## 3. 取れなかったもの・限界

- 観光庁のADR・RevPAR：調査項目にない。
- 観光庁の都道府県別2026年8月：1次速報には都道府県別がない（2次速報待ち）。
- JHRとインヴィンシブルのホテル別月次：(未)。JHRは地域別のみ、インヴィンシブルはサイトのメンテナンス中で確認できなかった。
- JHR・インヴィンシブルの地域区分（例「関西（大阪除く）」「首都圏（東京23区除く）」）は複数の都府県にまたがるので、都道府県には割り振らず表で併記した。インヴィンシブルは地域別のホテル数が書かれていない。
- 森トラストリートの前年比：(未)。
- 観光庁の地図は7月、J-REITの地図は8月で、対象月がそろっていない（それぞれの最新）。
- J-REITの都道府県値は1〜2ホテルだけの県が多く、1軒の改装・イベントで大きく動く（例：熊本県 RevPAR +50.3%は2ホテル）。

## 4. 毎月の更新手順（案）

新しい月が出たときだけ取り直す。

1. 観光庁（毎月末ごろ。例：8月2次速報は2026-10-30予定）
   - https://www.mlit.go.jp/kankocho/tokei_hakusyo/shukuhakutokei.html の「推移表」リンク先URLが変わったか、推移表の「4-1」シートに新しい月の列が埋まったかで判定する。
   - 変わっていたら `CONFIG["mlit_month"]` と `mlit_files` のURLを更新して実行。1次速報は全国値だけなので、都道府県の地図は2次速報で更新する。
   - 2027年1月分からは前年（2026年）も新系列シートに入るので、前年同月の読み先（今は「旧4-2」など）を変える。
2. J-REIT（各社とも翌月25日前後。星野は翌々月上旬）
   - TDnet（https://www.release.tdnet.info/inbs/I_main_00.html 。直近1か月分だけ公開）で証券コード 8985・8963・3463・3287 の月次開示を探し、新しい月なら `CONFIG["reit_files"]` のURLを差し替える。JHRのExcel（J1）と星野のExcel（H1）は各社サイトのリンク先が更新されるので、そこからURLを取り直す。
   - 星野のExcelは期ごと（5〜10月期、11〜4月期）にシートが増える。新しいシートができたら `hoshino_sheets` の当月シートと、前年同月が入っているシートを指定し直す。物件の入れ替えがあったら `python3 fetch_dynamic_pages.py hoshino` で所在地マスタを作り直す。
   - 森トラストは `python3 fetch_dynamic_pages.py moritrust`。
3. `python3 build_area_map.py --refresh` を実行し、CSVの「検算_」列（観光庁公表値との一致）を確認してからPNGを差し替える。
